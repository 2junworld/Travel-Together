# Travel Together · 가족여행 웹앱

2026-11-21 개발설계서 기반의 Next.js · TypeScript · Tailwind · Supabase 구현입니다.

현재 배포된 Sites 버전은 **비공개 샘플 체험판**입니다. 로그인 계정과 실제 가족 데이터가 들어 있지 않으며, 편집 내용은 브라우저에만 저장됩니다. 실제 공동 사용 서버와 연결된 운영 버전으로 오인하지 마세요.

## 실행

Node.js 22 이상 권장.

```sh
npm ci
cp .env.example .env.local
npm run dev:next
```

- Supabase 설정이 없으면 자동으로 샘플 모드가 됩니다.
- `npm run build:production` — API가 포함된 Next.js 운영 빌드.
- `npm run build:preview` — 샘플 전용 정적 HTML/PWA 빌드, `out/` 생성.
- `npm run typecheck` — TypeScript 검사.
- `npm test` — 로컬 PostgreSQL 엔진에서 권한·트랜잭션 검증 및 계산 규칙 테스트.
- `npm run build` — 이 관리 환경에서는 정적 체험판, 일반 환경에서는 운영 빌드.

## 실제 공동 사용 연결

1. 새 Supabase 프로젝트에서 `supabase/migrations/001_travel.sql`을 DB 소유자로 한 번 실행합니다. 기존 프로젝트에는 무작정 적용하지 말고 충돌을 확인해 주세요.
2. `.env.local` / Vercel 환경변수에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 설정합니다. 공개 publishable key도 해당 변수에 사용할 수 있습니다. **service_role 키는 사용하지 않습니다.** `NEXT_PUBLIC_DEMO_MODE=false`로 둡니다.
3. Supabase Auth의 사이트 URL을 운영 도메인으로, 리다이렉트 허용 URL에 `https://<운영 도메인>/invite/**`를 등록합니다. 이메일 로그인 링크를 이용합니다. 운영 이메일 발송 설정은 프로젝트에서 확인해 주세요.
4. Vercel에 Next.js 프로젝트로 배포합니다. Build Command는 `npm run build:production`, Output Directory는 Next.js 기본값입니다. 체험판의 `.openai/hosting.json`은 Sites용이며 Vercel 배포 설정이 아닙니다.
5. 관리자 이메일로 로그인 → 새 여행 생성 → 설정에서 동행 가족 추가 → 성인 각자의 이메일로 초대 링크 생성 → 링크를 개별 전달합니다. 이 앱이 초대 이메일을 직접 발송하지는 않습니다.
6. 가오슝 여행은 날짜를 2026-11-27~12-01로 만든 뒤, 가족 구성을 확인하고 설정에서 ‘문서의 초기 데이터 가져오기’를 선택합니다. 공동 픽업은 등록 가족 전원, 가족 일정·준비물·TODO는 이관 실행자의 가족에 배정합니다. 단일 트랜잭션으로 이관하며 안정적인 행 키로 재실행 시 기존 항목을 덮어쓰지 않습니다.
7. 온라인 Google 지도는 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` 설정 후 사용합니다. HTTP referrer 및 Maps JavaScript API 제한, 사용량·과금은 Google Cloud에서 설정합니다. 키가 없거나 SDK가 실패해도 목록과 등록된 주소의 길찾기는 유지됩니다.

브라우저 공개 환경변수는 **빌드 시점**에 반영되므로 변경 후 재빌드해야 합니다.

## 구현 내용

- 모바일 하단 내비게이션 / 데스크톱 사이드바, 날짜 탭, 공개 범위 필터, 주소 없는 장소 표시.
- 일정·장소·준비물·TODO 추가·편집·삭제, 준비물/TODO 휴지통 복구.
- 출발·도착의 시간대 표시, 여러 날 숙박 표시, 미정 시간, 준비율, 마감 임박 업무, 다음 시간 지정 장소.
- 준비물 목록 이름·카테고리·수량·복수 담당자, 개인별 완료와 전체 완료 구분.
- TODO 상태·담당자 필터, 마감·담당자·우선순위 정렬.
- 실제 모드의 이메일 로그인, 가족 추가, 여행 초대 수락, 멤버 역할·가족 배정·제외, 마지막 관리자 보호.
- 서버 멤버십·공개 범위 검증, 직접 DB 읽기의 RLS, 직접 테이블 쓰기 금지, 트랜잭션 RPC와 Next API, 낙관적 버전 검사.
- 공동 일정 변경 제안 비교·승인·반려. 개인→공동은 선택된 제목·필드만 제안에 저장하고 승인 시 공동 사본 생성.
- 가족/개인 비공개 일정 상세는 별도 테이블과 조회 API에 저장하고 일반 조회·오프라인 저장에서 제외.
- 가족→개인 사본, 범위 변경 확인, 범위를 벗어난 연결·담당 해제.
- IndexedDB 저장, 비공개/자유 메모 제외, 서비스 워커 앱 셸, 오프라인 쓰기 차단, 재연결 재검증, 로그아웃 전파·저장본 잠금.

## 설계서와 구현상 차이 / 남은 검수

- 4종 리소스는 공통 범위·버전 규칙을 쓰는 `travel_items` 테이블로 구현했습니다. 종류별 데이터와 연결·담당자 배열은 JSONB이며, 허용 필드·같은 여행 참조·독자 범위·담당자 범위·변경 권한을 DB 명령 함수에서 검증합니다. 직접 테이블 쓰기는 허용하지 않습니다. 별도 종류별 테이블 및 연결 테이블과 구조는 다릅니다.
- 준비물의 목록/카테고리는 항목 필드로 묶습니다. 독립 그룹 레코드의 생성·삭제·복구와 상위 그룹 우선 복구는 아직 구현하지 않았습니다.
- 모든 수정 화면은 409 시 입력을 유지합니다. 최신 원본과 초안을 나란히 비교하는 별도 충돌 해결 화면은 아직 없으며, 최신 조회 후 다시 편집해야 합니다.
- 공개 범위 전환은 새 독자 범위와 메모·연결·담당 해제를 확인하지만, 개별 새 독자 이름/첨부의 정밀 미리보기는 아직 없습니다. 신규 파일 업로드, 고급 감사 이력·템플릿·알림은 제외했습니다.
- 오프라인 기본 정책은 자유 메모·예약 상세·첨부 제외, 여행 종료 후 현지 기준 7일 경과 시 다음 조회에서 삭제입니다. 실제 가족 데이터를 저장하기 전에 운영자가 보존기간과 저장 범위를 확인해야 합니다.
- 실제 Supabase 프로젝트·이메일 세션·4개 사용자와 2개 실제 여행을 사용한 통합 검수는 **미실시**입니다. 현재 테스트는 PGlite PostgreSQL 엔진에서 Auth/JWT 함수와 암호함수를 테스트 전용으로 대체해 실행합니다. 운영 SQL은 Supabase의 Auth와 pgcrypto를 사용합니다.
- Google 지도 키 연결·SDK 실제 로딩·도메인 제한 및 쿼터 실패는 **미검증**입니다.
- 브라우저에서 준비물 완료, 추가·삭제·복구, 오프라인 저장 완료 표시를 확인했습니다. Android Chrome / iPhone Safari / 홈 화면 추가 후 비행기 모드로 종료·재실행은 **미검증**입니다. 이 검수 전에는 운영 완료로 판단하지 않습니다.
- 초기 데이터는 첨부 문서에 있는 비민감 항목만 사용했습니다. 주소·좌표·운영시간은 검증 전이므로 입력하지 않았고 항공·숙소 정보도 출발 전 재확인이 필요합니다.

## 주요 파일

- `components/travel/TravelApp.tsx`: 앱 셸·모듈·폼·상태 흐름
- `app/api/travel/route.ts`: 세션 기반 API / 오류 코드 / no-store 응답
- `lib/travel/`: 계약, 권한 편의 함수, 날짜 계산, 샘플, 이관
- `lib/offline/snapshot.ts`: 사용자·여행별 허용 필드 스냅샷
- `scripts/generate-sw.mjs`, `scripts/build-preview.mjs`: 운영/체험판 셸 캐시 생성
- `supabase/migrations/001_travel.sql`: 스키마·RLS·트랜잭션 명령
- `tests/`: 권한·동시 저장·공동 게시·시간대 검증

Supabase나 Google 비밀 키, 원문 예약번호, PNR, 주문번호, 결제금액은 소스에 포함하지 않았습니다.
