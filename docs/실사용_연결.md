# 실제 가족 공동 사용 연결

현재 Sites 주소는 샘플 체험판입니다. 운영 대상은 https://travel-together-theta.vercel.app 이며 Supabase 서울 프로젝트와 DB를 연결했습니다. 로그인 주소·SMTP 및 실제 사용자 세션 검증 완료 전에는 가족 공동 사용 준비가 끝난 것으로 간주하지 않습니다.

## 먼저 필요한 계정 연결

ChatGPT에서 Supabase와 Vercel을 연결해 주세요. 연결되면 대상 프로젝트 확인 → DB 마이그레이션 → 환경변수 → 운영 배포 → 사용자 세션 검증 순서로 진행할 수 있습니다. 연결 전에는 실제 프로젝트를 생성하거나 키를 저장했다고 간주하지 않습니다.

새 프로젝트의 지역·요금제·메일 발신자와 가족 멤버는 계정 연결 후 확인합니다. 비용이 드는 업그레이드나 실제 가족 초대 이메일은 자동으로 실행하지 않습니다.

## 운영 설정

- Supabase에서 아래 SQL을 순서대로 적용합니다. 빈 신규 프로젝트 기준이며 기존 DB에는 충돌 확인 후 적용합니다.
  1. `supabase/migrations/001_travel.sql`
  2. `supabase/migrations/002_production_validation.sql`
  3. `supabase/migrations/003_packing_bag.sql`
- Vercel에는 `vercel.json`으로 Next.js/API 운영 빌드를 지정했습니다. 체험판의 정적 `out/`를 운영 서버로 등록하지 않습니다.
- 환경변수는 다음과 같습니다. 운영 URL·공개 키는 Vercel production 환경에 등록했습니다.

| 변수 | 값 |
|---|---|
| NEXT_PUBLIC_SUPABASE_URL | Supabase 프로젝트 HTTPS URL |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | publishable 또는 anon 공개 키 |
| NEXT_PUBLIC_SITE_URL | 최종 Vercel 운영 HTTPS 원점 |
| NEXT_PUBLIC_DEMO_MODE | false |
| NEXT_PUBLIC_GOOGLE_MAPS_API_KEY | 선택 사항. 없어도 목록/외부 길찾기 사용 가능 |

`service_role`, `sb_secret_` 키는 브라우저용 변수에 넣지 않습니다. `npm run check:production`은 설정의 형식과 샘플 모드 비활성화를 검사하며 연결 성공을 보장하는 검사는 아닙니다. 설정이 빠지면 운영 빌드를 중단합니다.

## 이메일 로그인

Supabase Auth의 Site URL을 운영 도메인으로, Redirect URLs를 `https://<운영 도메인>/invite/`와 `https://<운영 도메인>/invite/?**`에 맞게 설정합니다. 최종 도메인을 확인한 뒤 허용 패턴을 검증합니다. 로그인 링크는 초대 토큰만 보존하고 기존 샘플 여행 ID는 전달하지 않습니다.

기본 Supabase 이메일 발신은 프로젝트 팀원 주소로 제한됩니다. 가족 4명이 각각 이메일 링크로 로그인하려면 사용자 지정 SMTP 또는 지원하는 메일 발신 구성을 연결해야 합니다. 팀원 권한을 가족 전체에게 부여해 이를 우회하지 않습니다.

공식 문서:
- https://supabase.com/docs/guides/auth/auth-smtp
- https://supabase.com/docs/guides/auth/auth-email-passwordless
- https://vercel.com/docs/frameworks/full-stack/nextjs

## 여행 시작

1. 준세님 계정으로 로그인해 2026-11-27~12-01 여행을 생성합니다.
2. 가족 두 개를 구성하고, 성인 4명의 이메일과 가족 배정을 확인합니다.
3. 앱에서 개인별 초대 링크를 만들어 전달합니다. 초대는 대상 이메일과 로그인 이메일이 일치해야 합니다.
4. 가오슝 문서의 초기 데이터를 이관합니다. 항공/숙박은 준세님 가족 범위, 공동 픽업은 등록된 가족 범위를 확인합니다. 기존 샘플 편집 내용은 서버로 자동 이관되지 않습니다.
5. 각 휴대폰에서 온라인으로 여행 저장을 실행합니다. 저장 대상은 일정/장소/준비물/TODO이며 자유 메모·비공개 상세·첨부는 제외합니다. 여행 종료 7일 뒤 삭제되는 기본 정책을 운영 전에 확인합니다.

## 실제 연결 후 필수 검수

- 실제 이메일 로그인, 초대 수락·재클릭, 가족 2개/사용자 4개 데이터 격리.
- 두 계정 동시 수정의 충돌 처리, 2인 준비물 체크 후 1인 해제.
- 사용자 변경/로그아웃 시 이전 계정 저장본 차단.
- Android Chrome 및 iPhone Safari에서 저장 → 비행기 모드 → 앱 종료/재실행 → 읽기 전용 → 재연결.
- 실제 예약 상세 입력은 위 권한 검수 후 진행합니다.

실제 서비스 연결과 휴대폰 검수 전에는 '운영 완료'로 표시하지 않습니다.
